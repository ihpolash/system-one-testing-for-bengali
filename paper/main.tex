\begin{abstract}
\noindent Many applications need a model that picks one answer from a fixed list and says how sure it is.
Decision models do this in a single step, returning a probability for every option, but almost all tests of them are in English.
This paper tests them on Bengali, a language typed both in its own script and in Latin letters (``Banglish'').
I evaluated twelve systems zero-shot on five Bengali tasks: one hosted decision model (Jev), ten open decision models and, as a baseline, one general-purpose language model.
Among the systems run on the full test sets, Jev scored highest on all five tasks, but its lead over the closest open system is clear on only \jevSepN{} of them.
Converting the test text to Latin letters with a rule-based tool lowered every system's score, by \dropMinVal{} to \dropMaxVal{} points on average.
Romanization studies usually test such tool-made text, so I also used \dakN{} Bengali sentences that native speakers had written in Latin letters.
These sentences have no labels, so the measure is how often a system gives the same answer as it gives on the Bengali-script version.
All twelve systems did so more often for the native speakers' spelling than for the tool's, by \dakRuleDiffMin{} to \dakRuleDiffMax{} points.
Their ranking stayed broadly similar (Kendall $\tau=\dakTauRule$).
A single temperature fitted on Bengali data reduced calibration error in all \tsLowered{} cases where it was fitted, but less on romanized text.
Whether tool-made romanization also overstates the loss in accuracy on labelled tasks remains untested.
Code and per-item predictions are released.
\end{abstract}

\section{Introduction}
Many systems need to choose one answer from a fixed list: route a support ticket, flag a comment as abusive, or decide whether a sentence follows from another.
A decision model is built for this.
It reads a text and a typed question and, in a single forward pass, returns one probability per option, without generating any text.
Because the output is a probability, a pipeline can accept confident answers and pass the rest to a larger model or a person \citep{deusser2026jev,nandakishore2026laya}.
That only works if two things hold: the model is accurate, and its confidence means what it says.

This paper checks both on Bengali, where they have barely been tested, and adds a question that Bengali makes unavoidable.
Bengali has its own script, but much of everyday Bengali is typed in Latin letters (``Banglish'') with no standard spelling.
Studies of romanized text build their test data with a transliteration tool, which applies one rule per letter.
People do not type that way, so a model's behaviour on tool-made romanization may differ from its behaviour on what people actually write.

The evidence on both points is thin.
Almost all tests of decision models are in English, and the one study that moved to another language shows why that matters: on Chinese tasks Laya-multilingual scored 40.2\% where Jev scored 68.4\% \citep{wang2026chinesejev}.
For Bengali I found only the Belebele and SIB-200 numbers that ship with the Jev benchmark \citep{deusser2026jev}, and no study that asks whether a decision model's confidence still carries information in Bengali.
Studies of romanized Indic text report large losses, but only on tool-made text \citep{khullar2025scriptgap,jawad2026fivedialects}; for Bengali I found no comparison with romanization written by native speakers.

This paper therefore asks how decision models behave on Bengali, and whether tool-made romanization is a good stand-in for romanization written by people.
Four questions structure the results (Table~\ref{tab:overview}):
\begin{enumerate}[label=\textbf{RQ\arabic*}]
\item How accurate are the systems on Bengali script, and how much does rule-based romanization cost them? (Section~\ref{sec:acc})
\item Does a system's answer move as much under native-speaker romanization as under tool-made romanization? (Section~\ref{sec:dak})
\item Are the systems' probabilities reliable on Bengali text, and does a correction fitted on Bengali script carry over to romanized text? (Section~\ref{sec:cal})
\item Does a system's answer change when the options are reordered? (Section~\ref{sec:rot})
\end{enumerate}
For RQ2 I use the Dakshina dataset, in which native speakers romanized Bengali Wikipedia sentences by hand \citep{roark2020dakshina}.
The sentences have no task labels, so RQ2 measures consistency with each system's own Bengali-script answer, not accuracy.

The paper makes three contributions.
\begin{enumerate}
\item A zero-shot benchmark of twelve systems on five Bengali tasks, in Bengali script and under rule-based romanization, with paired comparisons to the strongest system, calibration and option-order analyses.
\item A comparison of tool-made and native-speaker romanization on \dakN{} sentences. Rule-based romanization moved every system's answers more than native speakers' spelling did, by \dakRuleDiffMin{} to \dakRuleDiffMax{} points, while leaving the ranking almost unchanged.
\item A release of the harness, every per-item prediction and two audit scripts that recompute the headline numbers and every reported interval from the released files (Section~\ref{sec:repro}).
\end{enumerate}
This is not the first Bengali result for a decision model, since Jev's Belebele and SIB-200 numbers exist.
Kev-9B, Kev-27B, d3-27B and Microsoft-Decision-1 are not covered.

\section{Related work}
\label{sec:related}
Table~\ref{tab:gap} shows what the closest studies cover.
In English, decision models have been tested for calibration \citep{nandakishore2026laya}, for annotation with open models \citep{ibrahim2026annotation}, for sensitivity to option names \citep{sun2026typesafe} and option order \citep{li2026readout}, and for cost and wording \citep{sharma2026typedbench}.
None of these covers Bengali.
Work in other languages is thin: Chinese-Jev trains a Chinese model \citep{wang2026chinesejev}, and one study compares Jev's cultural-value answers in English and Arabic \citep{asseri2026calibrated}.
Script robustness has been studied for generative models only \citep{khullar2025scriptgap,jawad2026fivedialects}, and always on tool-made romanization.
The large Bengali romanization corpus of \citet{gharami2025romanized} is also generated by rule rather than typed by people.
For calibration and selective prediction I use standard measures \citep{guo2017calibration,geifman2017selective}; the option-rotation test follows \citet{zheng2024selectors}.
The benchmark described next is built to fill these gaps. Its tasks are Belebele \citep{bandarkar2023belebele}, SIB-200 \citep{adelani2023sib200}, MASSIVE \citep{fitzgerald2022massive}, SentNoB \citep{islam2021sentnob} and the Bengali translation of XNLI.

\subsection{Systems}
Two kinds of system are compared.
A \emph{decision model} is trained for typed decisions: it receives the question and the options as structured input and returns a probability for each option directly.
A \emph{general-purpose language model} is trained to generate text; to use one here, I read the probability it assigns to each option label as its next word.
Eleven of the twelve systems are decision models; Gemma-4-E4B-it is the general-purpose baseline, included to show what a model without decision-specific training achieves.

Jev (\texttt{jev-1.13.0}) is reached through its API; the open systems ran on a 15 GB Kaggle T4 GPU.
\begin{itemize}
\item \textbf{Encoders.} Laya-multilingual, built on mmBERT \citep{marone2025mmbert}; laya-bangla v2, a Bangla fine-tune of it; and Julia-1, with 144M parameters.
\item \textbf{vLLM-SR Decision 3.0} \citep{liu2026vllmsr}: d3-edge, d3-lite, d3-nano, d3-mini and d3-flash. d3-flash has 9B parameters and ran in 4-bit NF4 on a hash-ordered subset (about \flashNmax{} items per task, 500 Dakshina sentences).
\item \textbf{Kev 1.0}: Kev-0.8B and Kev-4B, served with the project's own code in bf16 with its shipped temperature. Their model cards list English as the only language. Kev-4B ran with CUDA-graph replay and the prefix cache switched off to fit in memory; these settings change speed and memory, not the model.
\item \textbf{General-purpose baseline.} Gemma-4-E4B-it. Each option is scored by the next-token probability of its label, normalized over the options.
\end{itemize}
Kev was run on the test sets and the Dakshina sentences only, so it has no development-split or rotation results.
Kev-9B, Kev-27B and d3-27B do not fit on the GPU, and Microsoft-Decision-1 is available only through an API that I did not use.
Identifiers and revisions are in Table~\ref{tab:models}; all settings are in \texttt{docs/MODELS.md}.

XNLI-bn and MASSIVE are cut to the first 1,500 items in hash order, so every smaller run is nested in a larger one.
The question structure for every task is in \texttt{docs/PROMPTS.md}; sources, checksums and licences are in Table~\ref{tab:prov}.

\paragraph{SentNoB split.}
I used the test split of the Hugging Face mirror \texttt{sadi2oo3q/SentNoB}.
Its train, validation and test splits hold \snMirrorTrain{}, \snMirrorValidation{} and \snMirrorTest{} comments, which add up to the \snPaperTotal{} of the original paper.
Other sources give a different test size: \snBlubTest{} in the BanglaBERT benchmark and \snLayaBanglaCardTest{} in the laya-bangla model card. I could not trace the difference.
Every SentNoB number in this paper uses the same \snFullN{} comments.
The mirror's test split also overlaps its training split: \snTestInTrain{} test comments (\snTrainPct\%) appear verbatim in it.
This cannot help a system evaluated zero-shot, unless the system was trained on SentNoB; laya-bangla's authors state that it was not, and I cannot check the others.
Removing all overlapping comments moves every system's macro-F1 by at most \snMaxShift{} points (Table~\ref{tab:snover}).

\subsection{Text conditions}
\label{sec:conditions}
\textbf{Bengali script} is the dataset text.
\textbf{Rule-based romanization} maps each letter to Latin letters with a fixed rule set and no diacritics. It is applied to four of the five test sets; Belebele passages are left in Bengali script.
\textbf{Natural-style romanization} replaces each word with its most frequent spelling in a public corpus of typed Banglish (\texttt{nahidstaq/bangla-transliteration-data}) and falls back to rules tuned on held-out words from that corpus.
\textbf{Native-speaker romanization} is the Latin-script text in Dakshina, which native speakers wrote for each sentence without a transliteration tool; a second group of annotators transcribed it back to Bengali script to validate it \citep{roark2020dakshina}.

The corpus behind the natural-style romanizer contained \lookupRemoved{} Dakshina sentences together with their native-speaker romanization.
My first natural-style romanizer had therefore seen the target spellings, and it scored \dakLeakJevNat{} for Jev.
I removed every corpus pair that matches a Dakshina string, rebuilt the lookup from the remaining \lookupKept{} sentences and reran all systems; every natural-style number in this paper uses the rebuilt version.

\subsection{Measures}
\label{sec:measures}
\paragraph{Accuracy.} Accuracy for four tasks, and macro-F1 for SentNoB, its usual metric.

\paragraph{Agreement (RQ2).} Every system answers one seven-way topic question about each Dakshina sentence, with the SIB-200 topics, in four spellings.
Agreement is the share of sentences on which the system's top option is the same as its own answer on the Bengali-script sentence.
Agreement is not accuracy: a system that is wrong on the Bengali sentence can still agree with itself.
I also report the mean total-variation distance between the two probability vectors, and the agreement expected by chance, $\sum_c p_{\text{Bengali}}(c)\,p_{\text{romanized}}(c)$, which is \dakChance{} on average.

Box~1 gives one sentence as an example.
It was chosen to show the measure, and it is not typical of every sentence.
\begin{center}\small\fbox{\parbox{0.92\linewidth}{\textbf{Box 1.} A Dakshina sentence (English gloss: \emph{Eurogamer's Ellie Gibson cited the game Candy Crush as the ``best game of the year'' of 2013}).\\[3pt]
Native-speaker spelling: \emph{Eurogamerer eli giboshon candy crush gameti 2013 saaler ``bochorer shera game'' hishabe ulekh.}\\
Rule-based spelling: \emph{iurogemarer eli giboson kyandi krash gemotike 2013 saler ``bochhorer sera gem'' hisabe ullekh.}\\[3pt]
Jev answers \emph{\exBnChoice} on the Bengali sentence (probability \exBnConf), \emph{\exNsChoice} on the native-speaker spelling (\exNsConf) and \emph{\exRuleChoice} on the rule-based spelling (\exRuleConf). The sentence counts as agreeing under native-speaker romanization and as not agreeing under rule-based romanization. Of the \exSystems{} systems, \exKeepNs{} keep their Bengali answer under the native-speaker spelling and \exKeepRule{} under the rule-based one.}}\end{center}

\paragraph{Calibration (RQ3).} Each measure answers a different question.
\emph{Expected calibration error} (ECE, 15 equal-width bins) asks whether the stated probability levels match the observed accuracy.
\emph{Confidence minus accuracy} asks whether a system is overconfident (positive) or underconfident (negative) on average.
The \emph{Brier score} mixes calibration with how well a system separates right from wrong answers, so a low Brier score alone does not show good calibration.
For one item it is $\sum_{k=1}^{K}(p_k-y_k)^2$ over the $K$ options, with $y$ the one-hot label; a task's score is the mean over items.
It runs from 0 to 2, and a uniform guess scores $1-1/K$: \brierUniXnli{} on the three-option tasks and \brierUniMas{} on MASSIVE.
Brier scores from tasks with different $K$ are therefore not comparable.
\emph{Risk--coverage curves} show accuracy among the most confident answers as coverage grows.
ECE and Brier are computed within each task and averaged without weights over XNLI-bn, MASSIVE and SentNoB, so that no single task sets the value.

\paragraph{Temperature scaling and the confidence gate.}
Temperature scaling fits one scalar per system and task.
It minimizes the mean negative log-likelihood over a grid of 41 log-spaced temperatures from 0.2 to 6, on a 1,500-item development split that is disjoint from the test items and contains Bengali script only.
The fitted temperature is then applied unchanged to the test items in Bengali script and in rule-based romanization; no test label enters the fit.
The confidence gate uses the same development split: its threshold is the smallest one at which the accepted development items reach \gateTarget\% accuracy, with at least 5\% coverage.
Belebele and SIB-200 have no development split, and d3-flash and Kev were not run on one, so they have no scaled results.

\paragraph{Option order (RQ4).} Each item is asked three times, with the options in three cyclic rotations. The measure is the share of items answered identically all three times.

\subsection{Statistics and levels of evidence}
All intervals are 95\% percentile bootstrap intervals with seed 0.
On the test sets they resample premise or passage clusters (Belebele, XNLI-bn) or items, 1,000 times (400 for SentNoB macro-F1, 500 for paired differences).
On the Dakshina sentences they resample sentences, 1,000 times.
Every comparison between text conditions, and every comparison with Jev, is a paired difference on the same items.

I separate three levels of evidence.
\begin{enumerate}
\item \textbf{Primary.} The native-speaker minus rule-based agreement difference, one per system. As a check against twelve simultaneous comparisons, I repeat it at a Bonferroni-adjusted level (99.6\%, 5,000 draws).
\item \textbf{Interval-based, unadjusted.} The native-speaker minus natural-style difference and the paired differences to Jev. These intervals are not adjusted for multiplicity, and an interval that excludes zero is not a significance claim.
\item \textbf{Descriptive.} Rankings by point estimate, the accuracy cost of romanization, calibration, the confidence gate and option order.
\end{enumerate}
I report no significance tests.

\section{Results}
\label{sec:results}
The results follow the four research questions, and each subsection opens with its finding.
\subsection{RQ1: How accurate are the systems, and what does rule-based romanization cost?}
\label{sec:acc}
\paragraph{Jev scores highest, but its lead is clear on only \jevSepN{} of the 5 tasks.}
Jev has the highest point estimate on every task among the systems run on the full test sets (Table~\ref{tab:main}).
Paired over the same items, the closest open system trails Jev by \pdBel{} points on Belebele (95\% interval \pdBelLo{} to \pdBelHi) and \pdSent{} on SentNoB (\pdSentLo{} to \pdSentHi); both are Gemma-4-E4B (Table~\ref{tab:vsjev}).
On \jevTiedTasks, the interval of the closest open system reaches or crosses zero: d3-nano on XNLI-bn is at \pdXnli{} (\pdXnliLo{} to \pdXnliHi), and d3-mini on MASSIVE at \pdMas{} (\pdMasLo{} to \pdMasHi).
On those tasks I cannot separate Jev from the best open systems.
d3-flash, on its subset of 200 to 405 items per task, is above Jev on XNLI-bn by \pdFlashXnli{} points (\pdFlashXnliLo{} to \pdFlashXnliHi) and below it on Belebele by \pdFlashBel{} (Table~\ref{tab:flash}).

\paragraph{Rule-based romanization lowers every score.}
Every system is less accurate on rule-based romanization than on Bengali script, on every task where both were run (Table~\ref{tab:main} and Figure~\ref{fig:script}).
Averaged over the romanized tasks, the loss runs from \dropMinVal{} to \dropMaxVal{} points; it is \dropjev{} points for Jev.
Among the systems that answered all four romanized tasks, \dropBestName{} loses least, \dropBestVal{} points; on SIB-200 it keeps \accgemmaSibRom{} of its \accgemmaSibNat, where d3-mini keeps \accminiSibRom{} of \accminiSibNat.

\paragraph{The other systems.}
Kev-4B performs close to d3-lite: \acckevmdSibNat{} against \accliteSibNat{} on SIB-200 and \acckevmdSentNat{} against \accliteSentNat{} on SentNoB, but lower on XNLI-bn (\acckevmdXnliNat{} against \accliteXnliNat) and MASSIVE (\acckevmdMasNat{} against \accliteMasNat).
Kev-0.8B falls in the lowest group with d3-edge and Laya-multilingual, and both Kev models are well below Jev on every task.
laya-bangla improves on its base model on SIB-200 (\acclayabnSibNat{} against \acclayamlSibNat) and MASSIVE (\acclayabnMasNat{} against \acclayamlMasNat). It was fine-tuned on the training splits of both tasks, so these two scores are in-distribution.
On SentNoB, a system that always predicts the majority class scores a macro-F1 of \sentMajorityFone, and uniform random guessing \sentUniformFone.
Laya-multilingual reaches only \acclayamlSentNat, below random guessing.
Its SentNoB score also depends on the wording of the question: macro-F1 is \layamlSentDefault{} with the default instruction, \layamlSentOpts{} with option names only and \layamlSentBn{} with Bengali wording.
Julia-1 cannot take the 60 options of MASSIVE.

\subsection{RQ2: Do answers move as much under native-speaker romanization?}
\label{sec:dak}
\paragraph{Every system keeps its Bengali answer more often under native speakers' spelling.}
Under native-speaker romanization, all \dakSystems{} systems kept their Bengali-script answer more often than under rule-based romanization, by \dakRuleDiffMin{} to \dakRuleDiffMax{} points (Table~\ref{tab:dak} and Figure~\ref{fig:dak}).
The paired interval excludes zero for all \dakNsBeatsRule; at the Bonferroni-adjusted level it still does for \dakBonfRule, the exception being \dakBonfFail, the system closest to its floor.
For Jev the difference is \dakjevNsVsRule{} points (95\% interval \dakjevNsVsRuleLo{} to \dakjevNsVsRuleHi): it kept its answer on \dakjevNs{} of the sentences under native-speaker romanization and on \dakjevRule{} under rule-based romanization.
The largest difference is d3-edge's, \dakedgeNsVsRule{} points.
The probability vectors agree: the total-variation distance from the Bengali answer is smaller under native-speaker romanization for every system (Table~\ref{tab:daktv}).

\paragraph{A romanizer tuned on typed Banglish closes little of the gap.}
Natural-style romanization differs from rule-based romanization by only \dakNatDiffMin{} to \dakNatDiffMax{} points.
It keeps the Bengali answer more often for \dakNatBeatsRule{} systems, makes no detectable difference for \dakNatTied{} and is worse for \dakNatLosesRule.
For Jev the difference is \dakjevNatVsRule{} points (\dakjevNatVsRuleLo{} to \dakjevNatVsRuleHi).
Native-speaker romanization is ahead of natural-style for all \dakSystems{} systems, by \dakNsNatMin{} to \dakNsNatMax{} points, with an interval that excludes zero for \dakNsBeatsNat{} of them.

\paragraph{The ranking hardly changes.}
Over the \dakNTau{} systems with all \dakN{} sentences, Kendall $\tau$ between the ranking under native-speaker romanization and under rule-based romanization is \dakTauRule.
So rule-based romanization preserves a broadly similar ranking of the systems, but it moves their answers further.
This result covers Wikipedia sentences and one topic question, and it measures consistency, not correctness.

\subsection{RQ3: Are the probabilities reliable?}
\label{sec:cal}
This analysis covers the \calFull{} systems with full test sets. Temperature-scaled results cover the \tsSystems{} of them with a development split; Kev has raw results only (Tables~\ref{tab:caltasks} and~\ref{tab:calbrier}).

\paragraph{The systems are overconfident on Bengali, by very different amounts.}
Averaged over the three tasks, every one of the \calFull{} systems has mean confidence above its accuracy.
This does not hold on every task: \calUnderCells{} of \calCells{} system-task cells are underconfident (\calUnderNames).
Raw ECE on Bengali script runs from \eceminiNatRaw{} for d3-mini to \ecejuliaNatRaw{} for Julia-1 (Table~\ref{tab:cal}).
On Bengali script, \brierWorseBn{} of \brierCellsBn{} system-task cells have a Brier score worse than a uniform guess; on rule-based romanization, \brierWorseRule{} of \brierCellsRule{} do (Table~\ref{tab:brtasks}).

\paragraph{One temperature fixes most of it on Bengali script, less on romanized text.}
A temperature fitted on Bengali development data lowered ECE on Bengali test items in all \tsLowered{} system-task cells where it was fitted. These are the \tsSystems{} systems on three tasks, \tsPossible{} cells, less \tsMissing, which it cannot take.
Averaged over the \tsSystems{} systems, ECE falls from \eceMeanRawBn{} to \eceMeanTsBn{} on Bengali script and from \eceMeanRawRule{} to \eceMeanTsRule{} on rule-based romanization.
After scaling, ECE remains higher on romanized text than on Bengali script for \tsRomHigher{} of the \tsRomSystems{} systems; \tsRomExc{} is the exception.
The risk--coverage curves (Figure~\ref{fig:rc}) show that confidence still ranks answers within each condition, but rule-based romanization lowers accuracy at every coverage level.

\paragraph{A confidence gate set on Bengali script does not carry over.}
On MASSIVE, the gate accepts \gatejevNatCov\% of Jev's Bengali items (\gatejevNatN) at \gatejevNatAcc\% accuracy, but only \gatejevRomCov\% of rule-based romanized items (\gatejevRomN), at \gatejevRomAcc\%.
For d3-mini it accepts \gateminiNatCov\% (\gateminiNatN) at \gateminiNatAcc\% and \gateminiRomCov\% (\gateminiRomN) at \gateminiRomAcc\%.
Jev and d3-mini keep accuracy near the target by refusing most romanized input.
For laya-bangla the gate fails: the accepted romanized items are \gatelayabnRomAcc\% accurate, although with only \gatelayabnRomN{} accepted items this figure is close to an anecdote.
These results rest on one task and are descriptive.

\paragraph{What tool-made romanization can and cannot tell.}
Rule-based romanization ranked the systems almost as native speakers' spelling did, but it moved their answers further.
For the systems and sentences tested, a tool-made test set therefore preserved a broadly similar ranking of the systems but overstated how much their answers move on Banglish written by people.
I did not measure whether it also overstates the loss in accuracy, which would need labelled sentences romanized by native speakers.
Why the native speakers' spelling is easier is untested.
One possible reason is visible in Box~1: people keep English loan words in English spelling (``candy crush'', ``game''), the form models have likely seen in web text, while the rule-based romanizer respells them (``kyandi krash'', ``gem'').
Comparing agreement on sentences with and without English loan words would test this.

\paragraph{Choosing a system for Bengali.}
\begin{itemize}
\item If the input is in Bengali script and an open system is needed, d3-mini, d3-nano and Gemma-4-E4B come within a few points of Jev on several tasks.
\item If romanized input is likely, Gemma-4-E4B loses least among the systems that answered all four romanized tasks, but its raw probabilities are among the least reliable (ECE \ecegemmaNatRaw) until a temperature is fitted.
\item If decisions depend on confidence thresholds, fit them on data in the same script as the deployment input; a threshold set on Bengali script does not carry over to romanized text.
\item Encoder systems need extra checks: their answers change with option order, and Laya-multilingual's SentNoB score changed by more than 10 points with the wording of the question.
\end{itemize}

\paragraph{The finding most likely to change.}
The size of the native-speaker advantage is the finding I would expect to change most with other data.
It was measured on edited Wikipedia sentences romanized by annotators, who may spell more carefully than people typing quickly on a phone.

\section{Limitations}
\label{sec:limits}
The limitations are ordered by how much each restricts the main claims.
\begin{enumerate}
\item \textbf{No labels for the native-speaker comparison.} RQ2 measures agreement with each system's own Bengali answer, not accuracy, so I cannot claim that tool-made romanization overstates the \emph{accuracy} loss on real Banglish.
\item \textbf{One kind of text and one question.} The Dakshina sentences come from Wikipedia and are asked one seven-way topic question, so I cannot claim that the same gap holds on the five tasks, on informal social-media text, or on other question types.
\item \textbf{Unknown annotators.} I do not know how many people romanized the Dakshina sentences or how their spelling compares with everyday typing, so I cannot claim the results represent Bengali speakers in general.
\item \textbf{Romanization of the five tasks is tool-made only.} The accuracy losses in RQ1 come from rule-based romanization, so I cannot claim they show how accuracy falls on Banglish that people type.
\item \textbf{Translated test data and possible contamination.} XNLI-bn and MASSIVE are translations, so SentNoB is the only native Bengali text. Training-data overlap is unknown for Jev, Gemma and the d3 models, and laya-bangla was fine-tuned on MASSIVE and SIB-200. I cannot claim the scores are free of contamination.
\item \textbf{The SentNoB split.} It comes from a third-party mirror, differs in size from other sources and overlaps its training split. The overlap moves no score by more than \snMaxShift{} points, but I cannot claim this split is the one other studies used.
\item \textbf{Incomplete coverage.} d3-flash ran in 4-bit on subsets; Kev has no development-split or rotation results; larger Kev and d3 models were not run; Julia-1 cannot take MASSIVE. Claims about these systems are correspondingly narrower.
\item \textbf{One prompt format per system family.} Laya-multilingual's wording sensitivity shows that a different format can move a result, so I cannot claim the rankings are independent of the prompt.
\end{enumerate}

\section{Conclusion}
On five Bengali tasks, Jev has the highest scores, and several small open systems come close on Bengali script.
Rule-based romanization lowers every system's accuracy, and on sentences that native speakers romanized, it also moves every system's answers more than the native speakers' spelling does, while ranking the systems in almost the same order.
A temperature fitted on Bengali script corrects most of the open systems' overconfidence, but less on romanized text.
These results come from Wikipedia sentences without labels and from tool-made romanization of the five tasks; measuring the accuracy loss on real Banglish needs labelled sentences typed by many people.

\section{Reproducibility and availability}
\label{sec:repro}
The repository is at \url{https://github.com/ihpolash/system-one-testing-for-bengali}.
There are three levels of reproduction, from cheapest to complete.
\begin{enumerate}
\item \texttt{make paper} rebuilds this PDF from the committed source, generated tables and numbers.
\item \texttt{make audit} (Python, \texttt{requirements.txt}) recomputes the headline numbers and every reported interval from the released predictions with an independent bootstrap, and checks every released file against \texttt{results/MANIFEST.sha256}. Both of these steps run from a fresh clone.
\item \texttt{make collect tables release figures} rebuilds everything from the raw model outputs. These outputs, the Jev response cache and the Kaggle logs are not released, so this step needs the models to be run again: a TypeSafe API key for Jev and a GPU for the open systems (\texttt{kaggle/}).
\end{enumerate}
The released files are the harness, the analysis code that generates every table and number in this paper, the result tables, per-item predictions for all systems on the test sets and on the Dakshina sentences, and checksums.
For Jev, only the top choice and its confidence are released, because its raw responses and probability vectors fall under the provider's terms.
The predictions contain no dataset text, except Belebele's option labels, which are Bengali text (CC BY-SA 4.0).
The Dakshina predictions are keyed by sentence identifier, and \texttt{data/make\_dakshina.py} rebuilds the sentences from the public dataset (CC BY-SA 4.0).
SentNoB's text is not included, because its authors' repository states no licence; the predictions do list SentNoB item identifiers, labels and predictions.
Model revisions, package versions and dataset licences can change over time; the ones used are listed in Tables~\ref{tab:prov} and~\ref{tab:models}.
